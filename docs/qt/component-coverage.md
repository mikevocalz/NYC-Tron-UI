## Counterpart boundaries

### Profile workspace

**building-blocks** — `ApplicationWindow`, `Item`, `RowLayout`, `ColumnLayout`

Keep the existing React tree, router and document state. Window/layout correspondence does not add a second QML UI owner.

References: [Qt controls](https://doc.qt.io/qt-6/qtquick-controls-qmlmodule.html), [Qt quick](https://doc.qt.io/qt-6/qtquick-qmlmodule.html), [Qt layouts](https://doc.qt.io/qt-6/qtquicklayouts-qmlmodule.html).

### Profile choice

**control-family** — `ComboBox`, `ButtonGroup`, `RadioButton`

Comparable selection control; option identity, callbacks and platform presentation stay in the public RN contract.

References: [Qt controls](https://doc.qt.io/qt-6/qtquick-controls-qmlmodule.html).

### Profile dock

**building-blocks** — `Drawer`, `Popup`, `SplitView`

Docking is a composition. Preserve platform navigation, focus and fold/hinge behavior.

References: [Qt controls](https://doc.qt.io/qt-6/qtquick-controls-qmlmodule.html).

### Profile split

**control-family** — `SplitView`, `SplitHandle`

Comparable resizable panes; existing sizing and document-state contracts remain authoritative.

References: [Qt controls](https://doc.qt.io/qt-6/qtquick-controls-qmlmodule.html).

### Profile tabs

**control-family** — `TabBar`, `TabButton`, `StackLayout`

Comparable tabs and content layout. Route/state preservation still belongs to the application.

References: [Qt controls](https://doc.qt.io/qt-6/qtquick-controls-qmlmodule.html), [Qt layouts](https://doc.qt.io/qt-6/qtquicklayouts-qmlmodule.html).

### Profile toolbar

**control-family** — `ToolBar`, `ToolButton`, `Action`

References: [Qt controls](https://doc.qt.io/qt-6/qtquick-controls-qmlmodule.html).

### Profile inspector

**building-blocks** — `Pane`, `GroupBox`, `ScrollView`, `TextField`, `Slider`

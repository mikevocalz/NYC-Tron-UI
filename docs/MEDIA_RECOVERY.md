# Media decoder and recovery controls

`@nyc-tron/platform-services/media` exposes `createPlatformMediaDecoder()`. Native iOS uses Expo v2 / AVFoundation on a serial worker. Android uses an Expo v2 module over MediaExtractor and MediaCodec (added after alpha.4 in `c903eba`); its Kotlin compiles, but no APK, emulator or device run has exercised it (`docs/completion/reports/P03-android-native-validation.md`). In alpha.4 Android reported `isAvailable: false`. Web uses a muted video/canvas for JPEG and WebAudio for interleaved PCM. Import the media subpath to avoid loading specialized UI.

Requests use integer microseconds. Frames fit a 4096-edge maximum (1920 default); audio spans are at most 60 seconds, 8–192 kHz, and native PCM is capped at 256 MiB/32 channels. Web audio accepts source files up to 64 MiB and 60 seconds because decodeAudioData decodes the whole source; browser-internal decoding allocations are not streaming or proven bounded. Web output uses samples; iOS output is a little-endian Float32 interleaved file. Native cache files total at most 256 MiB after successful writes, evicting oldest files. Returned URIs are temporary and may be removed by subsequent decoding, clearCache or OS pressure; copy through the app's writer for durable storage. The separate Forge byte cache requires explicit host keys/put calls and is not automatically populated.

Frame `timing` is presentation on native and seek-target on web. Web `actualTimeUs` is the settled currentTime and is not an exact decoded presentation timestamp. Network/codec/CORS failures reject with MediaDecodeError. Codec availability depends on the real platform. Web probe cannot describe audio tracks before decode.

`@nyc-tron/ui/components/forge/audio/AudioInterruptionRecoveryDialog` accepts a controlled notice: paused (reason plus ready), reset, or recording (actual filename). Supply the required callbacks for that notice and onClose. A paused host must confirm readiness before Resume is enabled. Callbacks may be async; actions stay disabled until completion and errors keep the dialog open. The component neither resumes automatically nor owns playback, native resources, recording persistence or engine state. Mount a new instance for a distinct recovery incident. The consuming app owns styling, event-to-notice policy and real recovery storage.

Expo prebuild/CocoaPods/Xcode Debug simulator app compile/link pass with the decoder present in ExpoModulesProvider and existing modules retained. Native decoder execution, OS interruption/recording recovery, Android decoding, physical devices and screen-reader acceptance remain open. No app window/orientation or Android manifest contract changed.

Recovery source is original project work; no ArtCraft implementation or assets were imported. The WebM fixture is generated from FFmpeg testsrc and sine filters.

Install

You are offline. Both install methods download from GitHub, so they need a connection. Everything on this page stays readable.

Registry (shadcn CLI)

Each item is copied into your app as source, with the items it depends on. Peers are not installed for you; each page lists them.

npx shadcn@latest add @nyc-tron/Button

Registry install is unverified until a clean app installs from the live URL. Registry URLs use ref `main`, a moving ref, until the owner cuts a release tag. They resolve only after this branch is merged to main. Before that, test against a local server. Use the release tarball until then.

You are offline. The install command needs a connection.

Add the namespace to components.json. shadcn rejects unknown keys, so platform targets are not in this file; see components-contract.md.

{
  "registries": {
    "@nyc-tron": "https://raw.githubusercontent.com/mikevocalz/NYC-Tron-UI/main/r/{name}.json"
  }
}

Item JSON is served at https://raw.githubusercontent.com/mikevocalz/NYC-Tron-UI/main/r/{name}.json, on the moving ref main until a release tag is cut. It resolves only after this branch is merged to main; before that, test against a local server, where {name} keeps its slashes (shell/UnitInput). Find an item with npx shadcn@latest search @nyc-tron -q "context menu".

After a registry install, import from the installed path, for example @/components/nyc-tron/ui/components/Button. shadcn add rewrites the @/components prefix to aliases.components. The tarball package @nyc-tron/ui does not exist in that app. Every component page shows both imports under "Registry install" and "Tarball install", and its example uses the registry one.

Native packages cannot be added this way. A registry add copies files and cannot run pod install, gradle, CMake, nitrogen or a WinUI build. They install from the tarball and are listed in registry-excluded.json.

Release tarball

This is the install path that works today. Copied from the README, section "Installing from a release".

The packages are not on npm. Each tagged release (v*) attaches one .tgz per package to a GitHub Release, plus a SHA256SUMS file. Pin the tarball URL in the consuming app's package.json:

https://github.com/mikevocalz/NYC-Tron-UI/releases/download/v<version>/nyc-tron-<name>-<version>.tgz

<name> is the package name without the @nyc-tron/ scope, for example nyc-tron-reserved-regions-1.0.0.tgz and nyc-tron-windows-fluent-fabric-1.0.0.tgz.

For a published v1.0.0 release (these candidate URLs become usable after release):

{
  "dependencies": {
    "@nyc-tron/core": "https://github.com/mikevocalz/NYC-Tron-UI/releases/download/v1.0.0/nyc-tron-core-1.0.0.tgz",
    "@nyc-tron/ui": "https://github.com/mikevocalz/NYC-Tron-UI/releases/download/v1.0.0/nyc-tron-ui-1.0.0.tgz",
    "@nyc-tron/panes": "https://github.com/mikevocalz/NYC-Tron-UI/releases/download/v1.0.0/nyc-tron-panes-1.0.0.tgz"
  }
}

Install only the packages you import. Sibling packages are peer dependencies, because a tarball cannot fetch @nyc-tron/* from a registry: @nyc-tron/panes needs @nyc-tron/core from the same release listed next to it. Workspace package exports point at compiled dist/*.js and dist/*.d.ts. The isolated Windows Fabric adapter also ships its typed native codegen source, which RNW needs when building its host; it belongs in an RNW 0.85 app, separate from Expo 58.

Peers: react and react-native are required by ui, panes and native-controls. panes also needs zustand. native-controls needs expo and @expo/ui (it is an Expo module with SwiftUI and Compose views). expo-controls needs expo, @expo/ui and zustand. In ui, every peer except react and react-native is optional and only needed by the subpaths that import it; importing Button pulls none of them. Support policy lists the subpaths that need react-native-skia, and [packages/ui/README.md](packages/ui/README.md) covers the others.

To check the tarballs before pinning them, download them with the release's SHA256SUMS and verify:

gh release download v1.0.0 --repo mikevocalz/NYC-Tron-UI \
  -p SHA256SUMS -p 'nyc-tron-core-*.tgz' -p 'nyc-tron-ui-*.tgz'
shasum -a 256 -c SHA256SUMS --ignore-missing

--ignore-missing skips the packages you did not download. pnpm records each tarball's integrity hash in the lockfile on first install, so later installs fail if a release asset changes.

Add NYC-Tron UI to an Expo app

Both paths use one command with the release tarball URLs. <v> is the release version without the leading v:

npm install --allow-remote=all \
  https://github.com/mikevocalz/NYC-Tron-UI/releases/download/v<v>/nyc-tron-core-<v>.tgz \
  https://github.com/mikevocalz/NYC-Tron-UI/releases/download/v<v>/nyc-tron-ui-<v>.tgz

npm 12 refuses remote tarballs unless --allow-remote permits them; npm 11 ignores the flag. Do not use npx expo install with tarball URLs: with Expo CLI 58 and npm 12 it fails with EALLOWREMOTE and writes an "undefined" key into package.json.

New app. npx create-expo-app@latest my-app --template blank-typescript, run the command above in my-app, then render a component:

import { Button } from "@nyc-tron/ui/components/Button";

export default function App() {
  return <Button title="Hello" onPress={() => {}} />;
}

Existing app. Run the same command in the app and add a screen that imports from @nyc-tron/ui. The command changes only package.json and package-lock.json. If the app uses Expo Router's NativeTabs (the default SDK 58 template does), a new route file is not shown on iOS and Android until the tab layout has a NativeTabs.Trigger for it; that is app code, not something the install does. The web layout needs nothing. An app from the default Expo SDK 58 template keeps the react-native-gesture-handler 3.3.x that Expo pins: from this commit, @nyc-tron/ui declares the optional peer >=3.3.0 <4 (V1_DECISIONS D5, decision 1). The v1.0.0-rc.1 tarballs still declare >=3.4.0 <4 and fail this step with ERESOLVE; with them, run npx expo install react-native-gesture-handler@^3.4.0 first.

Desktop app (Spark or React Native Windows). Spark 0.0.3 ships React Native 0.83.10 and React Native Windows 0.85 ships 0.85.3, below @nyc-tron/ui's react-native >=0.88 floor. The desktop lanes are below ui's React Native floor; only components on the lane's support list are supported. Add this override to the app's package.json, then run the same command:

"overrides": { "@nyc-tron/ui": { "react-native": "$react-native" } }

The override applies only to @nyc-tron/ui's react-native peer and points it at the app's own react-native dependency. Do not use --legacy-peer-deps, which drops every peer check in the tree.

@nyc-tron/ui needs no config plugin. Native projects come from npx expo prebuild (or npx expo run:ios / run:android, which prebuild first); no native file is edited by hand. The [install-paths workflow](.github/workflows/install-paths.yml) runs both paths on clean runners for web, the iOS simulator and the Android emulator, and the desktop install in the Spark and React Native Windows lanes, where the native app renders Button.

Peers and theme

Required peers: react, react-native. Optional peers, needed only by the subpaths that import them: @expo/ui, @tanstack/react-table, expo-drag-drop-content-view, expo-linear-gradient, react-native-gesture-handler, uniwind, zustand, react-native-skia. Each component page lists the ones it uses on its Peers: line.

The app defines 13 colour variables and 2 radii. See the tokens page. A missing variable does not fail the build.

For agents

Paste this into an agent that has a terminal and a URL fetcher:

Read https://raw.githubusercontent.com/mikevocalz/NYC-Tron-UI/main/llms.txt first. It lists every page. Fetch one page at https://raw.githubusercontent.com/mikevocalz/NYC-Tron-UI/main/docs/components/<id>.md, where <id> is the registry item id (for example shell/UnitInput). Use the token names in the page front matter; never colour or spacing literals. Install with npx shadcn@latest add @nyc-tron/<id> once the registry check passes, otherwise use the release tarball. Imports differ by install: after a registry install use @/components/nyc-tron/ui/components/<id>, after a tarball install use @nyc-tron/ui/components/<id>. Examples use the registry form.

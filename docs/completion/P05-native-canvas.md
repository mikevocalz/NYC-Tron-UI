# P05 native canvas checkpoint

The final 39-step scenario passed unchanged twice per platform: iOS 25.1s / 18.9s and Android 50.8s / 33.8s. The iOS passes followed device-scoped service recycling after a dead CoreDevice transport; Android used Argent’s managed guest-Vulkan boot. The rebuilt app includes Skia 3.9.1 and RNGH 3.4.0; the iOS GPU reports Metal and Android reports Vulkan. Android runs the emulator’s SwiftShader software renderer, not a physical GPU. Its drawn rectangle was visually inspected inside the existing usable pane. The existing default orientation and supported rotation entries remain intact. [Full output and limits](P05-native-canvas-proof.json) retain the evidence.

The scenario scrolls to the canvas examples, performs a native pinch and observes a controlled commit, replaces the document, opens the real GPU surface and checks sequential submissions for zoom and document replacement. A throwing renderer submits no frame and reports its actual error; recovery increments the submission count. The final checks prove the error text appears in the native tree and disappears on recovery. Every transition has an identity check and idle readiness. The final YAML uses semantic selectors and a selector-anchored pinch, with no raw points, fixed sleeps or device IDs.

Runtime review fixed two issues: touch-start points are retained before recognizer activation so early pinch travel is included, and cancelled contacts stay ineligible until released; error states release the image accessibility grouping so native tools can reach the alert text. Contact ownership clears on scope changes and termination. Android review also fixed a redundant initial submission: an initial active AppState notification no longer counts as a return from background/inactive. The final pinch selector uses the stable viewport identifier on both native platforms. All 32 affected canvas/selection browser tests, 841 source tests, UI build/type checks and native-consumer types pass after these changes.

The initial first-scroll attempt did not expose its target, and the discovery AX tree did not expose a Text testID. Those unmet waits were replaced by successfully recorded behavior and archived outside acceptance. The recorder's app auto-detection produced raw tap fallbacks; the finished test replaces them with the observed labels and the complete replay validates those selectors. A separate recorded follow-up supplied the new visible/hidden error checks before composition into the final scenario.

These are simulator interaction and observed rendering checks. They do not measure native frame presentation timing, hardware gamut, physical accessibility speech, desktop/headset acceptance. The Android debug build completed with Skia/RNGH native modules and the verified merged manifest. The implementation review count stays 97 of 341 at this native checkpoint. P05 continues with the remaining canvas, selection and layer components.

# PDF signatures, forms and capture

Reviewed K-04, K-06 through K-09 and K-18 through K-20.

SignatureStampTool shares the native RNGH/Graphite ink owner for drawing and erasing. The host creates an actual ink/image artifact and supplies the PDF placement preview; normalized position, width and rotation changes request host updates. Visible stamps do not claim certificate signing. Form fields expose native text, checkbox, choice and signing workflows, read-only/required metadata, host errors and revision-matched validation acknowledgements.

Voice attachments share NativeAudioTransport and measured recording waveforms. Only actual recorded artifacts can be attached, with source duration, byte count, MIME type and page anchors. ScanSession displays the native camera surface, requests capture and real correction, reorders pages, and appends or explicitly confirms replacement. Native handles and image/PDF/audio processing remain host-owned.

PointEditor2D supplies one active 44pt native RNGH grip, numeric coordinates and geometry/scope cancellation. Signatures and scan corners share it. Search and comment lists now virtualize results/threads. Annotation and PDF speech page actions recheck the active document and available targets. Existing third-party notices remain intact; new capture/signature controls are original implementations.

Validation: combined UI TypeScript build passed. Full source/browser/native rendering, gestures, camera/microphone permissions, PDF processing/signing, accessibility and persistence acceptance remain deferred until user review. All PDF rows now have UI implementation checkpoints; this does not establish production engine acceptance.

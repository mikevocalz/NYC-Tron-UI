# MIDI measure grid and controlled horizontal scrolling

MIDIPianoRoll now accepts a musical timeSignature tuple. PPQ remains ticks per quarter note; denominator beats and measure boundaries are drawn at their rational tick positions. A 5/8 bar spans 2.5 quarter notes, a 3/8 bar spans 1.5, and 6/8 spans 3. No rounding changes note starts, note lengths or snap precision. Existing callers retain the integer beatsPerBar contract when timeSignature is absent. The bounded grid helper still reduces long clips to at most the existing 256-line drawing budget.

The optional scrollX prop requests a nonnegative horizontal offset in layout points. The actual grid viewport is measured before restoring; requests and retained offsets are clamped to the current content bounds. Imperative ScrollView handles and measured/pending positions remain refs. Reached offsets are acknowledged through the existing onScrollX callback, so a velocity lane can use the same position. A user drag cancels a pending programmatic restoration; obsolete scroll events from a superseded restoration are ignored. Unmounted bodies cannot mutate the retained scroll position. The existing uncontrolled path retains its offset through note/geometry body replacement, while scope/revision still resets document presentation identity.

Hosts can inspect the optional static MIDIPianoRoll.capabilities property. Version 1 declares rationalTimeSignature and controlledScrollX. This is attached to the existing component export, so a consumer pinned to an older package can check its absence without importing an unavailable named export. The Forge host must retain its explicit legacy limitation when that capability is absent; passing an unknown prop to the old alpha.4 component does not implement the new contract.

The implementation keeps the existing Zustand note-preview stores, scoped commit/error/cancellation owner, keyboard and native gesture adapters. It does not create a player, synth, audio context, native module, window contract or engine operation.

Rational grids, viewport restoration, native scroll event ordering, focus, text scaling, RTL and assistive technology remain acceptance work. Published alpha.4 assets and consumer pins are unchanged.

# P05 thumbnail resources and Android host setup

B-10 retains the existing LayerThumbnail owner, independent component/model exports and ProCraft notices. Component and loader-source namespaces now separate reused layer IDs across documents without changing the IDs delivered to the host loader. Late callbacks cannot retry another scope. Existing loading, empty, failure and stale-preview states remain distinct. Compact labelled failures support keyboard retry and native accessibility activation; decorative previews add no hidden interactive controls. Roomy retry layouts reserve enough height for their 44-point button.

The cache now catches invalid fulfilled raster output as a visible retryable failure, bounds admitted pending loads, supplies cooperative AbortSignals and invalidates old results after clear. Cleared pending snapshots change so mounted subscribers can request again. Stale images remain only in bounded cache entries, replacing the unbounded side map. Retained URI bytes are conservatively accounted, and exhausted byte/pending budgets show an explicit retryable error. Oversized source rasters are validated before allocation/decoding and reduced to a bounded preview before PNG encoding.

Validation passed all 835 source tests, UI build/type checks and all 15 affected browser tests. Regressions include malformed successful loads, clear before loader start, cooperative abort and late completion, pending admission, byte limits, evicted stale images, stable missing snapshots, namespace isolation, bounded encoding, retry recovery and compact keyboard retry. Thumbnail native runtime and eight-platform acceptance remain open.

The native Skia rebuild also revealed the acceptance app's default Android minimum was 24, below Skia 3's API 26 requirement. A persistent Expo config plugin now raises only android.minSdkVersion, retains a higher existing minimum and preserves all other Gradle properties. Three regression tests cover this and the existing default orientation. Actual prebuild retained the app manifest byte-for-byte; the merged debug manifest preserves every previous Expo metadata value, permission and activity layout field, and includes API 26 plus Vulkan 1.1. [Merged manifest proof](P05-android-merged-manifest-proof.json) records the values and expected Skia/RNGH autolink packages. Native arm64 compilation uses the API 26 toolchain; the Android build/runtime check is still in progress. No other app configuration was audited.

Review count is 97 of 341. P05 continues with selection, layer and remaining canvas controls.

# Audio targets and localized chrome

This source phase extends the existing audio controls rather than introducing another mixer or playback owner. TempoAndMetronome, MixingConsole, ChannelStrip, LevelFader, its native vertical renderer, PanControl, SoloMuteButtons and MixGroupBar accept the app's targetSize. The default remains 44 points; a comfortable host can request 48. The private audio-chrome helper validates the size once at each independent component boundary.

Tempo forwards that target to its canonical PrecisionScrubber and tap/signature/metronome controls. MixingConsole forwards it through channel strips to fader, pan and toggle controls, and through the mix-group bar. The existing strip grows by twice the cross-axis target increase so its two-button row and pan track fit; 44-point strips retain their existing width. Native vertical fader rails/thumbs stay centered as the interaction width grows; the gain input and existing buttons consume the target too. Gesture travel, dB taper, physical stereo direction, committed values and engine callbacks retain their existing owners.

App-owned labels cover tempo instructions, signature/beat names, metronome copy, group and channel toggle names, fader numeric/fine/reset actions, pan names/spoken values and the console's empty state. Formatting callbacks let a host choose its own sentence order. Undefined overrides preserve defaults; blank static tempo/group/toggle labels are rejected. Numeric dB/BPM/pan parsing and the underlying numeric readouts remain the existing contract. Channel routing metadata and meter-band copy are not localized by this phase. Optional insert racks and routing panels keep their independent APIs and are outside this target propagation batch.

The changes retain scoped-control pending/error/cancellation ownership, existing Zustand stores, native RNGH gestures and current host boundaries. No audio context, metronome output, meter stream, manifest, window contract or dependency is added. Targets describe source geometry, with existing travel lengths and custom caller styles still owned by the app; this is not universal native accessibility acceptance.

Validation: `pnpm --filter @nyc-tron/ui build` passed. The package typecheck (including public slot types) and `git diff --check` also passed. Per the review gate, no new browser/native/runtime suites were run. Comfortable density, long translations, text scaling, RTL and assistive technology still need the later acceptance pass. Published alpha.4 assets and consumer pins are unchanged.

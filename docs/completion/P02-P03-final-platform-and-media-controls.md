# Final platform and media implementation batch

Reviewed N-05 through N-08, N-12, N-17, N-20, N-21, D-01 and D-05.

The existing platform owners were inspected and reused: opt-out/throttled native haptics, FocusAndA11yLayer and adjustable semantics, scoped hardware-key dispatch/conflict handling, native document picker/share/security-scoped access and serialized playback lifecycle policy. Hardware dispatch now suppresses stale-map, disabled and unmounted handlers at committed boundaries. These services retain their existing native implementations and prior evidence; this review does not extend that evidence to new platforms or physical hardware.

SafeAreaFoldableLayout applies only unconsumed insets and passes the inset window-space origin to the existing AdaptivePaneHost planner. Fold features stay in their original window coordinates. Product/native resource state stays above layout changes. No app orientation, window size, navigation contract or manifest metadata changed. The final diff review also connected CAD node insertion/connection failures to their visible error surfaces.

AudioInterruptionRecoveryDialog scopes decisions to the active notice/document and preserves the dialog on rejected recovery. Resume requires host readiness; no automatic route-loss resume or synthetic recovered file is introduced. AccessiblePrecisionScrubControl reuses PrecisionScrubber's keyboard, switch, adjustable and numeric model with a migrated RNGH 3 native drag/tap transport. Native pointer recognition remains separate from value ownership.

NativeVideoPlayer is a leaf export of @nyc-tron/native-controls. iOS renders AVPlayerLayer through SwiftUI/UIViewRepresentable; Android renders VideoView/MediaPlayer through Compose AndroidView. Actual player position, duration, readiness, completion, error and seek-token acknowledgements drive status. A seek requires an explicit nonempty token; loading a source alone never forces a seek. Source replacement invalidates old observers/owners; teardown pauses/releases the player and removes callbacks. The app retains audio-focus arbitration and must keep the player mounted above changing panel layouts. Android position reporting has millisecond precision and is not claimed to prove exact frame presentation. Native player surfaces currently cover iOS/Android; other platform adapters are not claimed.

FrameAccurateScrubber shares native OS sliders on iOS/Android and the existing web seek bar. Approximate previews coalesce to one request in flight and one newest target. Frame counts exclude the past-end position. Final commits abort preview consumers, request exact host seeking and require a matching actual presented frame with presentation timing. Seek-target estimates reject. Codec work already submitted may drain on its native owner; the host must serialize those operations.

API references: [AVPlayer exact-tolerance seeking](https://developer.apple.com/documentation/avfoundation/avplayer/seek%28to%3Atolerancebefore%3Atoleranceafter%3Acompletionhandler%3A%29), [Android VideoView](https://developer.android.com/reference/android/widget/VideoView), [MediaPlayer seeking and playback parameters](https://developer.android.com/reference/android/media/MediaPlayer). New player sources use the repository's established Expo 58 native-view registration. Existing module registrations and platform configuration are preserved; no Expo Video dependency was added.

Validation: UI, panes, native-controls, hardware-keys and platform-services TypeScript builds passed. New Swift player syntax parsing passed. Public built-export targets in those five packages exist. This is not Xcode/Gradle compilation or runtime acceptance of the new player or gesture changes. Those builds and source/browser/native/accessibility/performance suites remain deferred until user implementation review, as requested.

All 329 library-scope rows now have implementation checkpoints. The other 12 canonical IDs remain visible as separately scoped engine/platform integration work. Full platform acceptance, release packaging and consumer upgrades are still open; existing published alpha.4 assets are unchanged.
